# Studio foundation E2E evidence

This directory distinguishes two proof layers:

1. `http-receipt.json` is generated by `tools.foundation_trial:run_trial` and drives actual uvicorn, SQLite, filesystem, FFmpeg, HTTP upload, saved-reference prepare, explicit dry-run, restart, project switch, and legacy upload-only flows.
2. `browser-*.jpg` files, when present, are actual rendered-browser captures produced separately with the sanctioned CUA in-app browser. The HTTP helper does not claim browser automation and does not pretend that Python replay drove CUA.

The journey is local-only (`127.0.0.1`), uses temporary storage and freshly generated synthetic media, selects `RECASTROOM_BACKEND=dry_run`, forwards no credential-bearing host environment keys, stops every uvicorn process it starts, and contains no absolute user path in public receipts.

4. Stopped and restarted uvicorn on the same data, closed the browser tab, opened a fresh rendered tab, and confirmed project/version/history restoration with result hidden, Run disabled, and no automatic submission.
5. Repeated version selection, reset, upload-only switch, and return to the project; visible history remained unchanged.
6. With no character selected after reset, submitted duplicate `reference-1.png` basenames and observed the actionable 422 plus no runnable job/history change; then prepared distinct uploaded source/reference files and confirmed the new job was recorded in the visible project.
7. Switched away and back once more; all three prepared jobs remained listed.

All pre-restart media/config/DB-seed files were byte-identical afterward. `workspace.sqlite3` changed only because the expected uploaded-reference job was added to project history (counts: 1 project, 1 character version, 3 prepared jobs).
